Q5 介绍你做过的最好的项目 + 项目中遇到的最大困难，怎么克服的？（对着简历聊，备 1 个就够） A（推荐讲美团充电宝，最像"真实工程"）： - 项目一句话：负责共享充电宝设备异常治理的后端模块，解决同一设备反复上报异常、误报多的问题。 - 做法：先拉历史告警数据做口径梳理，定位到重复告警的根因（设备状态回传时序抖动 + 规则阈值一刀切）；设计了去重合并 + 分级阈值策略，上线后同设备重复异常下降 58%、误报率降低约 21%。 - 困难与克服：初期误报压不下去，我不再凭感觉调规则，而是把 badcase 逐条归因分类，用数据说话定位到主要来源，针对性改策略后指标明显收敛。收获：先定口径、再定方案、用数据验证。 - （如被问 Text-to-SQL：把一步生成拆成指标解析 + SQL 生成 + AST 校验三段，可执行率 76.1%→89.4%；如被问科研：MSTGN 多时空图网络做冬小麦产量估测，精度较基线提升 10%—18%，发 SCI 2 篇。）

二、可能问到的技术题（数量极少，各备 30 秒版）

Q16 进程和线程的区别？ A：进程是资源分配的基本单位，线程是 CPU 调度的基本单位；进程间内存隔离，线程共享进程的地址空间。进程切换开销大，线程通信更轻量但需要处理同步（锁）问题。

Q17 什么是死锁？产生条件？ A：多个进程互相等待对方持有的资源而永久阻塞。四个必要条件：互斥、持有并等待、不可剥夺、循环等待；破坏任意一个即可预防，最常用的是按序申请资源。

Q18 进程同步与互斥？ A：互斥是同一时刻只允许一个线程访问临界资源；同步是协调多个执行流的先后顺序（如生产者-消费者）。常用工具：互斥锁、信号量、条件变量。

Q19 数据库为什么用 B+ 树做索引？ A：相比 B 树，B+ 树非叶子节点只存键不存数据，单页能放更多键，树更矮、磁盘 IO 更少；叶子节点成链表，范围查询高效；所有查询都落到叶子层，性能稳定。

Q20 事务的 ACID？ A：原子性（全部成功或全部回滚）、一致性（前后都处于合法状态）、隔离性（并发事务互不干扰，四种隔离级别）、持久性（提交后落盘不丢失）。MySQL InnoDB 通过 undo log、redo log、锁+MVCC 实现。

Q21 HTTP 和 HTTPS 的区别？ A：HTTPS = HTTP + TLS。明文 vs 加密（非对称交换密钥 + 对称加密传输）、80 vs 443、证书防中间人。三次握手建立 TCP 后再进行 TLS 握手。

Q22 Redis 缓存穿透/雪崩？ A：穿透是查不存在的数据打穿到数据库——用布隆过滤器或缓存空值；雪崩是大量 key 同时失效——过期时间加随机值、多级缓存、限流降级。

Q23 Java 里 == 和 equals 的区别？ A：== 比较引用（基本类型比值）；equals 默认同 ==，String 等类重写后比内容；重写 equals 必须重写 hashCode。

Q24 Python 的 GIL？ A：全局解释器锁，同一时刻仅一个线程执行 Python 字节码，多线程无法利用多核做 CPU 密集计算；CPU 密集用多进程，IO 密集多线程/协程仍有效。

Q25 你的 RAG/Text-to-SQL 用到哪些技术？（对齐简历的"AI 题"） A：RAG 链路：父子 Chunk 切分、向量检索 + 元数据过滤、Rerank 重排、引用溯源；Text-to-SQL：把一步生成拆为指标解析→SQL 生成→AST 语法校验三段，配合可执行性评测集迭代，可执行率 76.1%→89.4%。

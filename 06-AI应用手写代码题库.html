第〇章 · 看懂代码需要的最小 Python 知识（零基础必读）

这一章把你读后面所有题目需要的东西一次讲齐。每个概念都配：它是什么（类比）+ 它长什么样（例子）+ 在你项目里对应什么。读完这章，后面的代码你就能”读”了。

0.1 变量 = 贴了标签的盒子

question = "古北水镇门票多少钱？"
price = 128
answer = "退役军人可享半价"
  • question、price、answer 是标签（变量名），= 的右边是装进盒子的东西（值）；
  • 以后在任何地方写 question，就是在引用盒子里的那句话；
  • 名字随便起，但见名知意：question 一看就知道装的是问题。

在你的项目里：device_id = 42（42 号机柜）、n = 3（连失窗口取 3）——之前讲过的”心跳 30 秒、窗口 3 周期”，写进代码就是几个变量。

0.2 字符串、数字、布尔——三种最常用的”东西”

name = "李方好"        # 字符串(str)：一段文字，用引号包住
count = 46             # 数字(int)：能加减乘除
is_online = True       # 布尔(bool)：只有 True / False 两个值，表示"是/否"

注意：True 首字母大写（写成 true 会报错）。布尔就是心跳判定里的”在线/离线”。

0.3 列表 list = 一排编了号的储物柜

docs = ["退役军人半价", "开放时间9点到21点", "学生票八折"]
docs[0]        # 取第 1 格 → "退役军人半价"   （编号从 0 开始！）
docs[1]        # 第 2 格
len(docs)      # 一共几格 → 3
docs.append("夜场政策")   # 末尾新增一格
  • 编号从 0 开始是最容易错的地方：第 1 格是 [0]，第 3 格是 [2]；
  • 你项目里：检索回来的知识块就是一个列表 ["块1", "块2", ...]，取前 5 个就是对列表切一刀（docs[:5]）。

0.4 字典 dict = 通讯录（名字 → 电话）

device = {"id": 42, "status": "online", "battery": 80}
device["id"]          # 用"名字"查 → 42
device["status"]      # → "online"
device["city"] = "北京"   # 新增一条记录
  • 方括号里放的不再是编号，而是键（key），查出来的是值（value）；
  • 这就是 Metadata 的代码形态！{"scenic": "乌镇", "effective": "2025-06-01"}——之前讲的”文档块的结构化标签”，写出来就是字典；
  • 大模型 API 的 messages 参数也是字典：{"role": "user", "content": "问题"}。

0.5 for 循环 = 流水线，逐个处理

docs = ["块1", "块2", "块3"]
for d in docs:          # 每一轮, d 依次是 "块1"、"块2"、"块3"
    print(d)            # 这行缩进的代码, 每轮执行一次
  • 读法：“对 docs 里的每一个 d，做下面缩进的事”；
  • 缩进（行开头 4 个空格）是 Python 的语法，不是美观——缩进错了程序直接报错；
  • 你项目里：巡检”逐台设备跑规则”就是 for device in devices:。

0.6 if 判断 = 分岔路口

battery = 15
if battery < 20:                    # 条件成立 → 走这条
    print("电量异常，生成告警")
elif battery > 95:                  # 否则如果…
    print("电量过高")
else:                               # 都不成立 → 走这条
    print("正常")
  • 你项目里：if 失联次数 >= 3: 判离线——防抖逻辑的骨架就是 if。

0.7 函数 def = 榨汁机（放进去水果，出来果汁）

def ask(question):            # 定义: 函数名叫 ask, 收一个东西, 装进叫 question 的盒子
    answer = 调用模型(question)   # 内部加工
    return answer             # 出料口: 把结果交出去

# 用:
result = ask("门票多少钱")      # 放进去问题, 接住结果
  • def 是 define（定义）的缩写——定义函数时里面的代码并不执行，只是把榨汁机组装好；调用时（写 ask(...)）才真正转起来；
  • return 是出料口：函数算完把结果从这里交出去，交给等号左边的变量；
  • 完整体写法 def ask(question: str) -> str:——冒号后面的 str 是类型标注（“我收字符串、吐字符串”），给人看的备注，删掉也能跑（但面试写上更专业，FastAPI 拿它干活）。

0.8 try / except = 安全网（走钢丝下面垫的网）

try:
    data = 调用API()          # 这段可能出事
except Exception:             # 真出事了 → 不崩溃, 走这里
    data = None               # 给个兜底值
  • 没有 try：一步出错，整个程序当场崩掉；
  • 你项目里到处是它：API 会超时（重试逻辑）、模型输出可能不是合法 JSON（解析容错）、写文件可能失败（统计不影响主流程）——“防御性编程”就是提前想好每一步出错了怎么办。

0.9 import = 去工具库借工具

import jieba                    # 借来分词工具
from openai import OpenAI       # 从 openai 这个库里只借 OpenAI 这一件
import time, json, re           # 一次借几件
  • 别人写好的功能（分词、调模型、算时间）都在”工具库”里，import 就是借来用；
  • 借完用法是 工具.功能()，比如 jieba.lcut("小麦条锈病")、time.sleep(3)。

0.10 类 class = 图纸（一个模板，能造很多台机器）

class AskRequest:               # 一张图纸
    question: str               # 图纸规定: 每台机器都有 question 这个零件
    top_k: int = 3              # 零件有默认值

req = AskRequest()              # 按图纸造一台（这一台叫"对象"）
req.question                    # 用这台机器的零件
  • 你只需要记住：类是图纸，对象是按图纸造出来的实物；FastAPI 里定义”请求长什么样”就是画一张图纸。

0.11 读代码的三个手勢（后面拆解会反复用）

  1. x.y（点）= “的”：resp.choices 读作 “resp 的 choices”——开套娃的第一层；
  2. x[...]（方括号）= “取出来”：列表按编号取、字典按键取；
  3. 从右往左读赋值：a = b.c[0] = 先取 b 的 c、再取第 0 个、装进 a。

一、API 调用与重试（入门必会）

T1. 写一个调用大模型的函数（★默写级——整份简历的最小代码缩影）

题目：“写个函数，输入一个问题字符串，返回大模型的回答。”

① 这题在干什么（大白话）：大模型在远端的服务器上，你要跟它说话，就得通过”API”（应用程序接口——远程服务的标准通话方式，像打客服电话：按格式报需求，它给答复）。这个函数就是打包好一次通话：以后任何地方想问模型，调一下 ask("问题") 就行。

② 逐行拆解：

from openai import OpenAI

借工具：openai 是官方提供的通话工具库（DeepSeek 兼容它的格式）。借来 OpenAI 这个”电话机类”。

client = OpenAI(api_key="sk-xxx", base_url="https://api.deepseek.com")

按图纸造一台电话机，起名叫 client。api_key 是你的身份凭证（钥匙，证明你是付费用户）；base_url 是打给哪家（不填默认 OpenAI，填 DeepSeek 的地址就是打给 DeepSeek）。这台”电话机”造一次全局复用，不用每次通话都造新的。

def ask(question: str) -> str:

组装榨汁机：函数名 ask，收一个字符串（问题），承诺吐一个字符串（回答）。

    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": question}],
    )

真正打电话的三行。从右往左读：client.chat.completions.create(...) = 电话机的聊天功能的创建方法——拨号。两个参数： - model：用哪个模型（车型选型）； - messages：说什么。它是一个列表，里面装字典——每个字典代表一句话，role 是说话人身份（user=用户 / system=设定 / assistant=模型），content 是内容。这里就一句：用户问 question。 返回的 resp 是一个大包裹（响应对象）：里面有正文、有 token 用量等很多层——正文藏在包裹深处，下一步拆。

    return resp.choices[0].message.content

拆包裹：resp 的 choices（候选回答列表，一般就一个）的 第 0 个 的 message（消息体）的 content（正文文字）。四层套娃，一层层点下来才是人话。return 交出去。

完整成品（默写目标）：

from openai import OpenAI

client = OpenAI(api_key="sk-xxx", base_url="https://api.deepseek.com")

def ask(question: str) -> str:
    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "user", "content": question}],
    )
    return resp.choices[0].message.content

③ 最容易错的地方： - messages 是列表套字典：[{"role": ..., "content": ...}]——最外层方括号忘写、role 拼错（不是 “user”），都直接报错； - 四层取值顺序背熟：choices[0].message.content——面试紧张时最容易断在这。

④ 面试口头讲：“定义函数收问题字符串；用全局复用的 client 调 chat 接口，messages 里放一条 user 消息；响应是个多层对象，取 choices 第一个的 message 的 content 返回。”

追问①：messages 里还能放什么？ → 三种角色：system（开场设定，如”你是文旅客服，只依据材料回答”——立规矩的位置）、user（用户问题）、assistant（模型历史回答）。多轮对话就是把历史 user/assistant 交替塞进去——所谓”上下文”，本质就是每次把历史完整重发一遍。 追问②：怎么让输出稳定/控制长度？ → temperature（0 最稳定，适合抽取类任务；越高越发散）、max_tokens（限长）、要 JSON 加 response_format={"type": "json_object"}。

T2. 带重试的调用（考异常处理，高频）

① 大白话：电话偶尔占线（超时），占线就挂了再拨——但要有章法：别秒拨（对方正在忙，连着拨是补刀），别无限拨（打 100 次也没用的就认命上报）。

② 逐行拆解：

import time

def ask_with_retry(question: str, max_retries: int = 3):

多收一个参数”最多试几次”，给默认值 3——调用方不传就自动是 3（默认值语法，面试常考）。

    for attempt in range(max_retries):

range(3) 生成 0,1,2——循环三轮，attempt 是”这是第几次”（从 0 数）。

        try:
            return ask(question)

试着打电话。成功就直接 return 走人——后面全不用看。成功路径永远最短，这是好代码的特征。

        except Exception as e:
            if attempt == max_retries - 1:
                raise

出事了接住（as e 把错误信息装进 e 方便打印）。判断：这已经是最后一次了（attempt 从 0 数，第 3 次时 attempt=2=max_retries-1）——再失败就没有下一次，raise 把错误向上抛（交给调用方处理）。 为什么抛而不返回 None：返回 None 是”吞错”——调用方拿到 None 不知道是成功了答案为空还是彻底失败，查问题会查到疯；抛错让错误明明白白传下去。

            wait = 2 ** attempt
            print(f"第{attempt+1}次失败: {e}, {wait}s 后重试")
            time.sleep(wait)

指数退避：2**0=1s, 2**1=2s, 2**2=4s——越失败等越久，给对方喘息。f"..." 是格式化字符串（f-string）：引号前加 f，{变量} 会被替换成真实值。time.sleep(wait) = 等这么多秒再进下一轮循环。

③ 易错：最后一次的判断是 max_retries - 1 不是 max_retries（因为 attempt 从 0 数）——边界差一（off-by-one）是循环最常见的错。 ④ 口头加分：“生产里 except 会区分错误类型——429（限流）才值得重试，401（密钥错）重试一万次也没用。”（429 就是你开源计费插件里处理过的那个状态码。）

T3. 多轮对话函数（考上下文维护）

① 大白话：让模型”记住”前面聊过什么——办法不是它有记忆，而是每次把历史完整重发。这个函数维护一个”聊天记录本”（history 列表），每轮：追加用户的话 → 连同历史一起发 → 追加模型的回答。

② 逐行拆解：

def chat(history: list, user_input: str) -> str:
    history.append({"role": "user", "content": user_input})

history 是个列表，每条消息是个字典。先把用户这句追加到记录本尾部。

    resp = client.chat.completions.create(
        model="deepseek-chat",
        messages=[{"role": "system", "content": "你是文旅客服"}] + history,
    )

发送内容 = 一条 system 设定 + 全部历史。+ 把两个列表拼成一个（列表加法）。system 在最前面立规矩，历史跟在后面。

    answer = resp.choices[0].message.content
    history.append({"role": "assistant", "content": answer})
    return answer

取出回答，也追加进记录本（模型的回答成为下一轮的历史），然后返回。用完之后 history 里用户和模型的话交替排列——这就是”上下文”四个字的代码实体。

# 用法:
history = []
chat(history, "古北水镇门票多少钱")
chat(history, "学生半价吗")     # 模型能懂"半价"指门票——因为第一轮在 history 里

③ 易错：忘了把 assistant 回答 append 回去——第二轮模型就”失忆”了。 ④ 口头升华：“这正是 LangGraph 状态对象里 messages 字段’追加式更新’的手写版。生产上历史越长 token 越贵，会做滑动窗口截断（见 T18）。”

二、RAG 检索链路（简历核心，最可能考）

T4. 手写一个最小 RAG（★★默写级——中青旅+神农两段实习的最小缩影）

① 大白话：开卷考试的程序版——翻书（检索）→ 把翻到的页摆在模型面前（组装材料）→ 命令它照着答（带强约束的提问）。20 行以内写完一个能跑的 RAG，面试官就知道你真做过。

② 逐行拆解：

import jieba

DOCS = {
    "d1": "退役军人凭有效证件可享古北水镇门票半价优惠。",
    "d2": "古北水镇开放时间为每日 9:00 至 21:00，夜场 17:00 入园。",
    "d3": "乌镇景区对全日制在校学生实行门票八折。",
}

知识库：字典（键是文档编号，值是内容）。真实系统里这一层是 Milvus 向量库，面试手写用字典模拟完全够——形状对了就行。

def rag_answer(question: str) -> str:
    q_words = set(jieba.lcut(question))

翻书第一步：把问题切成词。jieba.lcut("门票半价吗") → ["门票", "半价", "吗"]（列表）。再套 set() 转成集合——集合自动去重，且能做”交集”运算（下一步用）。

    def score(doc):
        d_words = set(jieba.lcut(doc))
        return len(q_words & d_words)

打分函数：把每篇文档也切成集合，q_words & d_words 是两个集合的交集（两边都有的词），len(...) 数有几个——问题里一半的词都在这篇文档里出现，它八成就是相关的。这是最朴素的”关键词检索”，思想就是 BM25 的婴儿版（共同词越多越相关）。

    top2 = sorted(DOCS.values(), key=score, reverse=True)[:2]

这一行三件事，从里往外读： - DOCS.values()：只要字典的”值”（文档内容），不要编号； - sorted(..., key=score, reverse=True)：按 score 打分从高到低排（key=score = “用哪个函数算排序依据”，reverse=True = 降序）； - [:2]：切前两个——这就是 Top-K（K=2），和 Top-5 命中率那个 K 是同一个东西。

    material = "\n".join(f"[{i+1}] {d}" for i, d in enumerate(top2))

把两段材料拼成一段文字：f"[{i+1}] {d}" 给每段编号（[1] xxx [2] xxx），enumerate 同时给出序号和内容，"\n".join(...) 用换行符把多段缝起来。为什么要编号——后面让模型标注”依据: 材料1”，可核查。

    prompt = f"""请仅根据以下材料回答问题，材料中没有的内容要明确说不知道。

材料：
{material}

问题：{question}"""

    return ask(prompt)

组装 Prompt（三要素全齐）：指令（仅依据材料 + 兜底话术”说不知道”）+ 材料 + 问题。三引号 """ 能跨行写字符串，{material} 被 f-string 替换成真材料。最后复用 T1 的 ask 发出去。 那一句”没有的内容要明确说不知道”就是压幻觉的灵魂——没有它，模型材料里没有也会硬编。

③ 易错：①key=score 写成 key=score(doc)（写括号就变成”立刻调用”，要传的是函数本身）；②忘 reverse=True（默认从低到高，取到的是最不相关的两篇——大冤种）；③三要素漏了兜底话术。

④ 面试口头讲（背这个顺序）： > “分词转集合 → 对每篇文档算词交集数打分 → 排序取前 K → 编号拼材料 → 组装带强约束的三要素 Prompt → 调模型返回。生产上三个升级：关键词换向量检索（认意思不认字面）、检索前加元数据过滤（先锁景区和生效时间）、粗排后加 Rerank 精排——正是我实习做的三件事。”

T5. 向量检索版（考 Embedding 概念的代码化）

① 大白话：T4 的打分是”数相同的字”，这里换成”量意思的距离”——把问题和文档都变成坐标（向量），算距离取最近的。面试官想看你懂不懂”语义检索”的形状。

② 逐行拆解：

from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics.pairwise import cosine_similarity

vectorizer = TfidfVectorizer(analyzer=jieba.lcut)

借两件工具：向量化器（把文字变向量）和余弦相似度计算器。analyzer=jieba.lcut 告诉它”中文请先用 jieba 切词再统计”。（教学用 TF-IDF 假向量；生产换成 bge 模型，接口形状完全一样。）

doc_ids = list(DOCS.keys())
matrix = vectorizer.fit_transform(list(DOCS.values()))

所有文档一起喂给向量化器学习并转换（fit_transform = 学规律 + 转换）——得到一个”文档 × 词”的矩阵，每行是一篇文档的向量。

def retrieve(question: str, top_k: int = 2):
    q_vec = vectorizer.transform([question])

问题也转成向量——注意用 transform 不是 fit_transform：坐标系的”规矩”必须用文档建的那套，新问题只转换不重建。类比：所有地址都用同一张地图标坐标，拿 A 地图的坐标去 B 地图上找位置没有意义——这就是”换 Embedding 模型必须全库重建向量”的原因（高频追问，背下来）。

    sims = cosine_similarity(q_vec, matrix)[0]

算问题向量和每篇文档向量的余弦相似度（方向越一致越相关），得到一排分数；[0] 是因为输入是”一批问题”，我们只有一个，取第一行。

    ranked = sorted(zip(doc_ids, sims), key=lambda x: x[1], reverse=True)
    return ranked[:top_k]

zip(编号, 分数) 把两列拉链式配对成 (编号, 分数) 元组；lambda x: x[1] 是”匿名小函数：取第二项（分数）当排序键”——lambda 就是现场定义的迷你函数，x: x[1] 读作”给我 x，我还你 x 的第 1 位”。排降序切前 K。

③ 易错：对问题用了 fit_transform（坐标系重建，相似度全乱）；lambda 里写 x[0]（按编号排序了）。

T6. 元数据过滤（考字典/列表过滤基本功 + 你的简历知识）

① 大白话：翻书前先锁书架——只留”本景区的、当前生效的”文档，再谈检索。这是你中青旅治”串召和过期政策”的那一招的代码版。

② 逐行拆解：

from datetime import date

CHUNKS = [
    {"text": "退役军人半价", "scenic": "乌镇",  "effective": "2024-01-01", "expired": None},
    {"text": "退役军人免票", "scenic": "乌镇",  "effective": "2025-06-01", "expired": None},
    {"text": "退役军人半价", "scenic": "古北水镇", "effective": "2023-01-01", "expired": "2024-12-31"},
]

每个块 = 一个字典：正文 + 三个标签（景区、生效日、失效日）。这就是”给文档块打 Metadata 标签”的代码实体。

def filter_chunks(chunks, scenic_id: str, today: date):
    def ok(c):

写一个”合格判定”小函数 ok：给一个块 c，回答 True（留下）/ False（踢掉）。

        if c["scenic"] != scenic_id:
            return False
        if date.fromisoformat(c["effective"]) > today:
            return False
        if c["expired"] and date.fromisoformat(c["expired"]) < today:
            return False
        return True

三道关卡逐一拷问：景区不是我要的 → 踢；还没生效（生效日在未来）→ 踢；已失效（失效日在过去）→ 踢；全过 → 留。 细节：date.fromisoformat("2025-06-01") 把日期字符串变成日期对象（变成对象才能比大小）；第三关的 c["expired"] and ... 是先判空再比较——expired 是 None（永不过期）时跳过比较，不判空直接比会崩。

    return [c for c in chunks if ok(c)]

列表推导式（读作”收集每一个通过考核的 c”）——等价于 for 循环 + append，但是一行。这是 Python 的地道写法，面试写出来加分。

③ 埋了一个面试官爱追的坑：上面数据里乌镇两条（2024 版、2025 版）都没标失效——同时”生效”怎么办？口头答：“这是真实踩过的坑：治理上要求新版本入库时给旧版本回填失效时间；查询侧按生效时间倒序取最新。”（数据治理意识，正是你实习里指标治理的同一思想。）

T7. 父子 Chunk 替换（考数据结构映射）

① 大白话：检索命中的是”小卡片”（子块），喂给模型前要换成”整页”（父块）——而且两三张卡片属于同一页时，那页只塞一次（重复塞浪费 token）。

② 逐行拆解：

PARENTS = {"p1": "门票优惠政策全文……", "p2": "开放时间全文……"}
CHILDREN = [
    {"id": "c1", "parent": "p1", "text": "退役军人半价"},
    {"id": "c2", "parent": "p1", "text": "学生八折"},
    {"id": "c3", "parent": "p2", "text": "夜场17点入园"},
]

两张表：父块库 + 子块列表（每个子块记着自己的 parent——这就是”父子关系”的存储方式：不是嵌套，是各自独立、靠 parent 字段关联，像户口本上写”父亲是谁”）。

def to_parents(hit_child_ids: list) -> list:
    parent_ids = []
    for c in CHILDREN:
        if c["id"] in hit_child_ids and c["parent"] not in parent_ids:
            parent_ids.append(c["parent"])

遍历所有子块：是命中的（in hit_child_ids）且它的父块还没收集过（not in parent_ids）→ 收录。第二个条件就是”同父去重”——c1、c2 都命中时，p1 只进一次。漏了它，材料里同一页出现两遍，token 白花。

    return [PARENTS[pid] for pid in sorted(parent_ids)]

按父块编号排序（p1 在 p2 前——保持文档里的原始顺序，材料顺序乱了模型阅读体验也乱）再取正文。又是列表推导式。

③ 易错：忘去重（最常见）；忘排序。

T8. 结构化输出 + 容错解析（考 JSON 解析与防御）

① 大白话：Text-to-SQL 第一段”指标解析”的手写版——让模型从一句话里抠出三个字段并输出 JSON。难点不在让它输出，在它偶尔不乖：会带上一句”好的，以下是结果：“或用 ```json 包裹——你的解析要像安检机，什么歪瓜裂枣都能处理。

② 逐行拆解：

T9. Prompt 组装函数（三要素模板）

① 大白话：把”给模型下命令”写成标准模板函数——以后所有问答都走它，改规矩只改一处。模板里每一条规则都对应一类线上 Badcase（面试时这句话值很多分）。

def build_prompt(question: str, materials: list) -> str:
    material = "\n\n".join(f"【材料{i}】{m}" for i, m in enumerate(materials, 1))

材料编号拼接。enumerate(materials, 1) 的 1 表示序号从 1 开始数（默认 0，给人看的编号从 1 顺手）。

    return f"""你是一名文旅客服, 遵守以下规则:
1. 只依据【材料】回答, 材料没有的明确回答"暂未查到相关规定"
2. 回答末尾标注依据, 格式: (依据: 材料N)
3. 涉及价格和时间时原样引用, 不做推算

{material}

用户问题: {question}"""

四要素：角色（文旅客服）→ 约束（仅依据材料 + 兜底话术 + 标依据 + 不推算）→ 材料 → 问题。 每条规则的”主治”：规则 1 治无依据生成（幻觉）；规则 2 给可核查性（Badcase 归因全靠出处标注——你中青旅定位串召就是看出处发现的）；规则 3 治模型自己算数算错（它不擅长算术，价格一律照抄）。

四、缓存与计费（呼应你的开源项目 DSH-plugin）

T10. 峰谷计费函数（考查表 + 分段逻辑）

① 大白话：你开源计费插件的核心逻辑——拿一次调用的 token 明细，先判断它发生在峰时还是谷时，再查对应价目表算钱。和电费单一个算法。

from datetime import datetime

PRICING = {
    "deepseek-chat": {
        "peak":    {"hit": 0.30, "miss": 9.0,  "output": 27.0},
        "offpeak": {"hit": 0.15, "miss": 4.5,  "output": 13.5},
    }
}

价目表：字典套字典套字典（模型 → 时段 → 三桶单价，单位：元/百万token）。查表代替一堆 if——加新模型只需加一行表，代码零改动（这也是”指标词典”的代码思想：规则进数据，不进代码）。

def compute_cost(model: str, usage: dict, ts: datetime) -> float:
    table = PRICING[model]
    hour = ts.hour
    band = "peak" if 9 <= hour < 12 or 14 <= hour < 18 else "offpeak"
    rate = table[band]

峰谷判定：北京时间 9-12 点、14-18 点是峰（注意两个区间的写法：9 <= hour < 12 数学式连写，Python 支持这样写；边界是”左闭右开”——9 点整算峰，12 点整算谷，能讲清这个边界就是加分）。"A" if 条件 else "B" 是 if 的单行版（三元表达式）。

    hit  = usage.get("cache_read", 0) + usage.get("cache_write", 0)
    miss = usage.get("input", 0)
    out  = usage.get("output", 0)

取 token 数。.get(键, 0) 而不是 [键]：键不存在时 get 返回默认 0，方括号直接 KeyError 崩掉——处理外部数据（模型返回的）永远用 get，因为你不能保证它每次都带全字段。

    return miss/1e6*rate["miss"] + hit/1e6*rate["hit"] + out/1e6*rate["output"]

三桶各自 ÷ 一百万 × 单价再相加（1e6 是 100 万的科学计数法写法）。完事——这就是”峰谷电价”的全部代码。

③ 口头呼应：“这是我开源计费插件的核心逻辑，真实代码还多了按计价带的累计统计和 jsonl 落盘。”

T11. 统计装饰器（考装饰器手写——技能栏点名考）

① 大白话：之前讲过装饰器是”不改函数本体给它加功能”。现在手写一个：给任意函数装一块”水表”——每次调用自动数 token、累计，原函数干什么完全不动。

import functools

total_tokens = {"value": 0}

全局累计数。为什么装在字典里而不是直接 total_tokens = 0：函数内要改外层变量，字典是”改盒子里的东西”（合法），裸数字是”换盒子”（Python 会当成新变量，踩坑点——用字典包一层是标准解法）。

def count_tokens(fn):
    @functools.wraps(fn)
    def wrapper(*args, **kwargs):

装饰器三板斧第一、二步：接收函数 fn → 定义 wrapper。*args, **kwargs 是”不管原函数收什么参数，原样接住”（位置参数进 args、关键字参数进 kwargs）——这样装饰器能套在任何函数上。@functools.wraps(fn) 是礼貌：保留原函数的名字和文档（不写的话函数改名叫 wrapper 了）。

        result = fn(*args, **kwargs)
        usage = getattr(result, "usage", None) or kwargs.get("usage", {})
        tokens = usage.get("total_tokens", 0)
        total_tokens["value"] += tokens
        print(f"[本次 {tokens} tokens, 累计 {total_tokens['value']}]")
        return result
    return wrapper

wrapper 内部四步：先调原函数（fn(*args, **kwargs) 是把接住的参数原样转交）→ 从结果里找 token 数（getattr(对象, "属性", 默认) = “有这个属性吗？没有给默认”）→ 累计 → 原样 return 结果（水表不改变水流——这句是灵魂）。 第三步斧：return wrapper 把包装好的交出去。

@count_tokens
def call_model(question, usage=None):
    ...

@ 语法糖 = call_model = count_tokens(call_model)——从此调 call_model 实际跑的是带水表的 wrapper。

③ 口头升华（必说）：“我的开源计费插件本质就是这个装饰器的流式加强版——在数据流上包一层，透传原样、末尾记账。”

五、FastAPI 异步服务（神农场景）

T12. 最小 AI 服务接口（★默写级——神农项目的最小缩影）

① 大白话：把 T4 的 RAG 从”本地函数”变成”网上的服务”——别人（前端页面、别的程序）通过网络 POST 一个问题过来，你返回 JSON 答案。十几行就是一个能跑的 AI 接口。

from fastapi import FastAPI

借两个工具：FastAPI（框架）和 BaseModel（数据校验图纸的基类）。app = FastAPI() 造出应用本体——之后所有接口都登记在它身上。

class AskRequest(BaseModel):
    question: str
    top_k: int = 3

画”收货单”图纸：规定请求体必须长什么样——question 必须是字符串（必填），top_k 是整数（有默认值 3，可不传）。FastAPI 拿这张图纸自动校验：对方发来 {"question": 123}（数字），根本进不了你的函数，直接被打回 422 参数错误——这就是”参数自动校验”，之前讲 FastAPI 时说的 Pydantic 在干这件事。

@app.post("/ask")

两件大事：①装饰器登记——“POST 到 /ask 的请求交给这个函数”（登记一次，之后全自动——还记得”你给格式和逻辑，流程它负责”吗，这就是那行登记）；②async def 声明这是可中断的函数（异步版榨汁机：遇到等待会让位给别的请求——烧水时去拿茶叶）。

函数体三步：检索（复用 T5）→ 组装 Prompt 调模型（await = “这里要等几秒，我先让位，好了叫我”）→ 返回 Python 字典，FastAPI 自动转成 JSON 发回去（你永远只管 return 字典）。注意 req.question：收货单里的字段用点取。

T13. 并发限流器（考异步锁——CapacityLimiter 的手写版）

① 大白话：索道限载——模型服务最多同时扛 10 路，第 11 个请求排队等着，完成一个放行一个。防止瞬时洪峰打爆下游（你神农项目干的事）。

import asyncio

class Limiter:
    def __init__(self, n: int):
        self._sem = asyncio.Semaphore(n)

图纸：造限流器时发 n 个”名额牌”（Semaphore 信号量 = 一摞名额牌的抽象）。__init__ 是”造机器时自动执行的初始化”。

    async def call(self, prompt: str):
        async with self._sem:
            return await ask_async(prompt)

核心两行：async with self._sem = 进门先取名额牌，没有就挂起排队（挂起不占 CPU——事件循环趁你去服务别的请求）；async with 代码块结束时自动还牌（with 语法的承诺：进来干什么，走时一定还）。牌子在手里才真正调模型。

limiter = Limiter(10)

@app.post("/ask")
async def ask_api(req: AskRequest):
    return {"answer": await limiter.call(req.question)}

全局限流器实例（10 个名额），接口里包一层。50 个请求同时来：10 个在调模型、40 个安静排队——这就是”避免瞬时请求造成服务拥塞”的代码实体（简历原话落地）。

口头追问：为什么不用多线程？→ 等模型是 I/O 等待不是计算，事件循环挂起零成本；线程每个占内存、切换有开销。N=10 怎么定？→ 压测下游看延迟拐点。

T14. 批量并发（考 asyncio.gather）

① 大白话：一个问题要问 5 个子问题——别排队一个一个问（5×3 秒=15 秒），同时问（约 3 秒）——等待时间重叠利用，就是”一个厨师看五锅”。

async def ask_multi(questions: list) -> list:
    tasks = [ask_async(q) for q in questions]
    return await asyncio.gather(*tasks)

两行：①列表推导式造 5 个”任务”（注意：造任务不等于开跑，协程此刻只是待命）；②asyncio.gather(*tasks) 一声令下全部开跑，等齐后按造任务的原顺序收结果（谁先完成都行，收的时候顺序不乱——这个保证要口头说出来）。*tasks 的 * 是拆包：把列表拆成一个个参数塞给 gather。

口头加分：“配合 T13 用——并发但不超下游承受力；return_exceptions=True 可以让单个失败不拖垮整批。”

        "desc": "查询城市天气, 参数: city(城市名)",
        "func": lambda city: {"city": city, "weather": "多云 26℃"},
    },
}

工具表：字典——工具名 → {说明书 desc, 真函数 func}。desc 是给模型看的（模型靠读描述决定用不用、怎么填参数——所以描述写不清就是”Tool 参数错误”的根源，你中青旅修的 Badcase 之一）；func 用 lambda 写了个假的（真环境里是查库/调 API）。

def agent(question: str, max_turns: int = 3) -> str:
    messages = [{"role": "user", "content": question}]
    for _ in range(max_turns):

对话记录 + 最多循环 max_turns 轮。for _ in ... 的 _ 是”我不关心这个变量，纯粹数次数”的惯用写法。为什么要封顶：模型可能反复要工具甚至死循环——防御性设计。

        tool_desc = "\n".join(f"- {n}: {t['desc']}" for n, t in TOOLS.items())
        raw = ask(f"""你可以使用以下工具:
{tool_desc}

如果需要工具, 只输出 JSON: {{"tool": "工具名", "args": {{...}}}}
如果不需要, 直接输出对用户的最终回答。

当前对话: {json.dumps(messages, ensure_ascii=False)}""")

每轮把工具说明书 + 当前对话 + 输出格式要求一起给模型，让它决策。json.dumps(..., ensure_ascii=False) 把对话列表变回字符串塞进提示（ensure_ascii=False 让中文不以 乱码显示）。

        try:
            call = json.loads(raw.strip())
            assert call["tool"] in TOOLS
            result = TOOLS[call["tool"]]["func"](**call["args"])

执行工具三步：解析模型的 JSON 指令 → 白名单校验（assert ... in TOOLS：模型可能编造不存在的工具名——这行就是”Tool 参数错误”的防线，漏了它模型让你调 delete_database 你也照干）→ 查表执行。**call["args"] 是字典拆包成关键字参数：{"city": "北京"} 变成 func(city="北京")。

            messages.append({"role": "assistant", "content": raw})
            messages.append({"role": "user", "content": f"工具结果: {json.dumps(result)}"})
        except Exception:
            return raw.strip()
    return "达到最大轮数限制"

结果回喂：工具结果作为新的 user 消息追加进对话，进下一轮循环——模型看到结果再决定”够了，给最终答案”还是”再要一个工具”。except 兜底：模型输出不是合法 JSON（说明它不想用工具了，直接给了答案）→ 把原文当最终回答返回。循环耗尽 → 明说达到上限（不装死）。

口头升华：“这就是 Agent 的本质——模型决策 + 程序执行 + 结果回喂的循环；LangGraph 只是把这套循环画成显式的图，节点单独测试、路由写在代码里，可控性强。”

T16. 意图路由（LangGraph 条件边的手写版）

① 大白话：医院分诊台——先判断来的是哪类问题，再决定走哪条流水线（病虫害的多查一步天气，普通问答直接 RAG）。

def route(question: str) -> str:
    if any(k in question for k in ("病", "虫", "枯", "斑", "锈")):
        return "病虫害"
    return "其他"

分诊函数：any(...) = “括号里任何一个条件为真就真”——问题里含这些关键词之一就判病虫害。（教学版用关键词；生产上让模型做选择题输出标签——这就是 query_process 节点干的事。）

def process(question: str) -> str:
    intent = route(question)
    if intent == "病虫害":
        weather = TOOLS["get_weather"]["func"](city="北京")
        return ask(f"结合天气数据 {weather} 回答: {question}")
    return rag_answer(question)

按意图分流：病虫害分支多走一步工具（查天气——湿度影响病害判断，神农的真实场景），其他走 RAG。route = 条件边，两个分支 = 两条执行路径——“根据不同农业场景组合执行流程”的代码实体。

七、手撕算法类（AI 岗也会考的经典）

T17. Top-K（和检索直接相关）

考法：“一堆 (文档id, 相似度)，取最高的 k 个。”

import heapq

def top_k(pairs: list, k: int) -> list:
    return heapq.nlargest(k, pairs, key=lambda x: x[1])

heapq.nlargest(k, 数据, 依据) = “按依据取最大的 k 个”——标准库一行搞定（面试先写这行，追问再手写）。手写版思路：维护一个大小为 k 的最小堆，新元素比堆顶（当前第 k 名）大就踢掉堆顶换进来——全程只跟 k 个元素较劲，O(n log k)。

追问：为什么不全排序？ → 全排序 O(n log n)；百万文档取 50 个，堆法快一个量级。Rerank 之后取 top5 就是这个场景。

T18. 滑动窗口截断（多轮历史管理）

def truncate(history: list, keep_turns: int = 10) -> list:
    return history[-keep_turns * 2:]

history[-20:] 的负号 = “从尾部数”——保留最近 20 条（一轮对话 = user+assistant 两条，所以 ×2）。列表切片负索引是这题唯一考点。

追问：截断丢了最早的信息怎么办？ → 生产做法：被截掉的部分摘要压缩成一条 system 消息（“此前对话摘要：…”）——信息不丢、token 大减。

T19. 分词去停用词

STOP = {"的", "了", "是", "在", "和", "有", "就", "不", "我", "你"}

def tokenize(text: str) -> list:
    return [w for w in jieba.lcut(text) if w.strip() and w not in STOP]

列表推导式带两个过滤条件：w.strip()（去掉纯空格的碎屑——strip 是去首尾空白）且不在停用词表里。STOP 用集合不用列表：集合的 in 是飞快查（哈希），列表的 in 要逐个对——数据量大时天壤之别（小优化，说出来是加分）。

追问：为什么去停用词？ → “的了我你”哪句话都有，毫无区分度——BM25 的”逆文档频率”思想：越常见的词越不值钱。

八、常见报错速查 + 默写练习法

8.1 看到这些报错先想到什么（考场自救表）

报错 意思 十有八九是
NameError: name 'x' is not defined 用了没定义的名字 变量名拼错 / 忘了先赋值 / 忘 import
IndentationError 缩进不对 少了或多了一层缩进（Python 靠缩进分块）
KeyError: 'xxx' 字典里没这个键 拼错键名；外部数据该用 .get(键, 默认)
TypeError: 'dict' is not callable 把不是函数的东西当函数调 多写了括号：sorted(x, key=score) 写成了 key=score(x)
IndexError: list index out of range 列表没这么长 编号从 0 起算错了 / 空列表取 [0]
JSONDecodeError 不是合法 JSON 模型输出带了废话——正则抠 {...} 再解析（见 T8）

8.2 默写练习法（48 小时冲刺节奏）

  1. 第一遍（对着文档抄）：T1、T4、T12 三题，逐行抄一遍——手熟从抄开始，不丢人；
  2. 第二遍（遮住答案默写）：写完对照，用红笔标出每一处和答案不一样的——标红处就是你的”个人漏洞清单”；
  3. 第三遍（隔天盲写）：只看题目名默写，能一次写对 90% 就算过；
  4. 其余题目做到”看着目录能口述每行在干什么”即可；
  5. 每题写完的口头三件套别忘了：思路先行 → 防御说明 → “生产上会升级成…”（勾连实习经历）。

8.3 最后的话

你不需要变成”会写代码的人”才能过这些题——你需要的是把这三题背成肌肉记忆（T1 调模型、T4 最小 RAG、T12 接口骨架），它们加起来不到 50 行，覆盖了你简历的全部关键词。其余题目理解形状、口述清楚即可。面试官考手写的目的不是看你是高手，是排除”完全没写过”的人——你只要明显在”写过”这一侧，就赢了。

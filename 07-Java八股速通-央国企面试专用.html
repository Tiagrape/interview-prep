〇、总地图：Java 知识版图（3 分钟建立框架）

先回答最基本的一题：Java 是什么、为什么到处是它？

Java 是一门”一次编写、到处运行”的语言：代码不直接交给操作系统跑，而是先编译成”字节码”，交给 JVM（Java 虚拟机）去执行——每台机器上装好 JVM，同一份程序哪里都能跑。

类比：字节码像”普通话”，各台机器（Windows/Mac/Linux）是听各地方言的人——只要每个人都会普通话（装了 JVM），你说一遍全国都懂。Python 是解释执行（同声传译，慢一点但灵活），Java 是先编译再跑（提前翻译好，跑得快）——这就是”编译型 vs 解释型”的直觉。

三个名词一句话分清（必考）：JDK（开发工具包=装修全套：编译器+调试器+JVM）＞ JRE（运行环境=精装房：能跑程序不能开发）＞ JVM（虚拟机=毛坯房：只管执行）。

Java 版图四块（就是本文档四章）： 1. 语言基础——怎么写对代码（语法和面向对象）； 2. 集合——怎么装数据（Java 的”数据结构库”，面试重灾区）； 3. JVM——代码在哪跑、内存怎么管（Java 引以为傲的”自动内存管理”）； 4. 并发——怎么同时干多件事（企业级服务必须面对的）； 5. 外加 Spring——Java 后端的事实标准框架（写接口必用，对应你的 FastAPI）。

一、语言基础

1.1 ★ == 和 equals 的区别（出镜率第一梯队）

类比：== 是比门牌号（是不是同一栋房子），equals 是比屋里的东西（两栋不同房子但摆设一模一样，也算”相等”）。

30 秒答案：== 比较的是两个变量装的是不是同一个对象（引用/地址）；equals 默认和 == 一样，但很多类重写了它来比”内容相等”——比如两个 new String("abc") 用 == 比是 false（两个对象），用 equals 比是 true（内容一样）。

追问下限：Integer 的坑——Integer a=127, b=127 时 a==b 是 true（-128~127 有缓存池），128 时是 false（新对象）。知道这个坑说明你真背过。

1.2 ★ String 为什么不可变（immutable）

类比：广播出去的话——新闻一发出去就不能改了，所有人听到的都一样。这看起来是限制，其实是安全：正因为不能改，大家才敢放心共享同一份（字符串常量池里存一份、处处复用），也才敢拿它当 HashMap 的键（键要是能变，存进去就找不到了）。

30 秒答案：String 内部的字符数组被 final 修饰且不提供修改方法，所以一旦创建内容不可变。好处三个：安全共享（常量池）、线程安全（没人能改就没有竞争）、哈希值稳定（适合做键）。每次”拼接”其实是新建了一个字符串——所以大量拼接要用 StringBuilder。

1.3 String / StringBuilder / StringBuffer

30 秒答案：String 不可变，适合当常量；要频繁拼接用 StringBuilder（可变、快、线程不安全）；多线程共享拼接用 StringBuffer（可变、慢一点、线程安全——方法都加了锁）。

类比：String = 刻好的碑文；StringBuilder = 草稿本（随便改）；StringBuffer = 带锁的共享草稿本（一次只让一个人写）。

1.4 ★ 面向对象三大特性

30 秒答案： - 封装：把数据和操作包进类里，对外只露必要的门（private 字段 + public 方法）——像自动售货机：你只管按按钮，机器内部不给你碰； - 继承：子类自动获得父类的属性方法，在此之上扩展——子承父业再创业； - 多态：同一个方法调用，不同对象有不同表现——“叫”这个动作：猫是喵、狗是汪。父类引用指向子类对象，运行时才知道具体调谁（Animal a = new Cat(); a.call() 叫出来的是喵）。

1.5 重载（Overload）vs 重写（Override）★

类比：重载 = 同一家店的”大份/中份/微辣/中辣”——同一个菜名（方法名），参数不同（份量辣度），是编译时就按参数选好；重写 = 子代改良祖传菜谱——方法签名完全一样，子类换成自己的实现，是运行时才决定调父类版还是子类版（多态的基础）。

30 秒答案：重载是同一个类里方法名同、参数列表不同（类型/个数/顺序），编译期按参数静态匹配；重写是子类覆盖父类的同签名方法，运行期根据实际对象动态绑定。一句话：重载是”横向扩菜单”，重写是”纵向改配方”。

1.6 接口（interface）vs 抽象类（abstract class）

类比：接口 = 合同/插座标准——只规定”必须有什么功能”（220V 两孔），不关心谁来实现（冰箱电视都能插）；抽象类 = 半成品图纸——已经做好了一部分共性（轮子和引擎），留几个空位让你补完（must 补”车型设计”）。

30 秒答案：接口只定义行为契约（JDK8 后可有 default 方法），一个类能实现多个接口；抽象类是”半实现的父类”，含已实现的方法，只能单继承。选择：要”能做什么”用接口（会飞、会游泳），要”是什么+共用代码”用抽象类。

1.7 ★ final / static / this / super

30 秒答案： - final：最终版——修饰变量=常量不可重新赋值，修饰方法=不可被重写，修饰类=不可被继承（String 就是 final）； - static：属于类而不是对象——不用 new 就能用（类名.静态方法），所有对象共享一份。类比：实例变量是每个员工自己的工位，静态变量是全公司的公告栏； - this：我自己（当前对象）；super：我爹（父类部分）——构造子里 super(...) 先让父类初始化。

1.8 异常体系 ★

类比：异常 = 跑步摔倒了怎么办。Error = 心脏病发作（你处理不了，程序该死就死，如内存溢出）；Exception = 摔了一跤——其中编译时异常是”裁判提前警告你这段路必摔”（不处理不让编译，如文件不存在），运行时异常是”跑着跑着踩空”（NullPointerException 空指针、数组越界，编码不细心导致）。

30 秒答案：Throwable 分两支——Error（严重错误，不捕获）和 Exception。Exception 又分编译期受检异常（必须 try-catch 或 throws 声明）和运行时非受检异常（NullPointerException、ArrayIndexOutOfBounds 等）。try-catch-finally：finally 无论是否异常都执行（用来关资源）——和你开源插件里”finally 记账保证不漏”是同一个东西，主动提这个勾连。

1.9 基本类型和包装类

30 秒答案：8 种基本类型（int、double、boolean…）不是对象、放栈里、速度快；对应包装类（Integer、Double…）是对象。自动装箱 = int → Integer（编译器自动 new），拆箱反之。需要对象的场合（集合里只能装对象、可为 null 表示”没填”）用包装类。

1.10 深拷贝浅拷贝（中频）

类比：浅拷贝 = 共享文档的链接（两份”文件”其实指向同一份内容，改一处两边都变）；深拷贝 = 另存为一份独立文件（各改各的互不影响）。

二、集合框架（★面试重灾区，HashMap 必考）

2.0 先建地图：两大门派

集合分两大类：Collection（单列，一个个装） 和 Map（双列，成对装）。 Collection 下有 List（有序、可重复——排队列表）、Set（不可重复——花名册）、Queue（队列，先进先出）； Map 是键值对（通讯录：名字→电话），键不可重复。 背下这张族谱就够了：List（ArrayList/LinkedList）、Set（HashSet/TreeSet）、Map（HashMap/TreeMap）。

2.1 ★★ HashMap 的底层原理（Java 面试第一题，没有之一）

类比：邮局的分格柜。 - 存东西：拿钥匙（键）算一个格子号——hash(键) % 柜子总数，直接放进那格——这就是”按 hash 定位”，不用从头翻找，所以快； - 两把钥匙算到同一格（哈希冲突）：格子里排一条队（链表，拉链法）； - 某格的队太长（长度 ≥ 8 且柜子够大）：排队升级成”按大小排好的树”（红黑树），查得快（链表变树，查询从 O(n) 到 O(log n)）； - 柜子装到 3/4 满（负载因子 0.75）：扩容搬家——柜子翻倍，所有东西重新算格子号（rehash）。

30 秒答案：JDK8 的 HashMap = 数组 + 链表 + 红黑树。put 时对键算 hash 定位数组下标，冲突则挂链表，链表长到 8 且数组长度 ≥ 64 转红黑树；容量超过阈值（容量 × 负载因子 0.75）就扩容为两倍并重新分布。查询平均 O(1)。

追问下限：①为什么容量是 2 的幂——位运算取模更快且散列均匀；②为什么线程不安全——两个线程同时扩容可能丢数据/成环，多线程用 ConcurrentHashMap；③键可以为 null（放第 0 格），只能一个。

2.2 ★ ArrayList vs LinkedList

类比：ArrayList = 电影院座位——编号连续，找 7 排 8 座一步到位（随机访问快）；但要插一个人进中间，后面所有人往后挪（中间插入慢）。LinkedList = 手拉手排队的小朋友——想插队只需松开两只手重新拉（插入删除快）；但问”第 100 个是谁”必须从头数（随机访问慢）。

30 秒答案：ArrayList 底层是动态数组，随机访问 O(1)、中间插删 O(n)（挪元素），扩容 1.5 倍；LinkedList 底层双向链表，插删 O(1)（改指针）、访问 O(n)。日常 90% 用 ArrayList——查多写少。

2.3 HashSet / HashMap 去重的原理

30 秒答案：HashSet 底层就是一个 HashMap（值是一个固定占位对象），靠键的 hash 和 equals 判断”是否已存在”——所以放进 HashSet 的对象要正确重写 hashCode 和 equals，否则去重失灵（两个”内容相同”的对象算出不同格子的号，各存各的）。

2.4 ★ ConcurrentHashMap 为什么线程安全

类比：** HashMap 是不带锁的公共储物柜（谁都能同时开同一格，挤成一团）；ConcurrentHashMap 是每格自带小锁的柜子——JDK8 里用 CAS + synchronized 只锁”当前这一个格子”**：锁的粒度小（桶级），别的格子照常存取，所以并发性能好（对比老方案 Hashtable 把整个柜子锁死——一段锁全场）。

2.5 Comparable 和 Comparator

30 秒答案：都是定”怎么比大小”。Comparable 是类自己实现的”天生比较规则”（compareTo，写在类里）；Comparator 是外挂的裁判（比较器对象，临时定制）——同一个员工列表，一会儿按工龄排一会儿按工资排，就是外挂不同 Comparator。类比：天生血型 vs 体检时自选检查项目。

三、JVM（虚拟机）

3.1 ★ JVM 内存结构（必考，画五个区）

类比：JVM = 一间大厨房，五个功能区：

区域 类比 装什么 特点
堆 Heap 大操作台/仓库 对象和数组（new 出来的都在这） 共享，GC 主战场
虚拟机栈 Stack 每个厨师自己的案板 方法调用的局部变量、调用帧 线程私有，方法一层层压栈弹栈
方法区/元空间 菜谱档案柜 类信息、常量、静态变量 共享
程序计数器 每人手里的进度条 记录当前执行到哪一行 线程私有
本地方法栈 进口厨具区 native 方法 了解即可

30 秒答案：线程共享的有堆（对象）和方法区（类信息静态量）；线程私有的有虚拟机栈（方法调用和局部变量）、程序计数器、本地方法栈。栈管运行（方法一层层进出），堆管存储（对象放这）——栈溢出 StackOverflowError 一般是递归太深，堆溢出 OOM 一般是对象太多或泄漏。

3.2 ★ 垃圾回收 GC（Java 的招牌卖点）

先答”哪些内存能回收”——可达性分析： 类比：保洁阿姨判断房间有没有人用，从大门（GC Roots：栈里的变量、静态变量等）出发挨个房间走——能走到的都是”在用的”（可达），走不到的整片区域连人带物一起清（不可达=垃圾）。比”数引用个数”（引用计数）可靠——两个垃圾互相拉着对方的手（循环引用），从大门照样走不到，照样清。

30 秒答案：判定垃圾用可达性分析：从 GC Roots 出发，不可达的对象即可回收。回收算法三个：标记-清除（标记垃圾直接扫，产生碎片）、复制（内存分两半，活的对象搬到另一半，整块清——新生代用，快但费空间）、标记-整理（标记后把活的挪到一端再清边界——老年代用，不产生碎片）。

追问下限（分代）：堆分新生代（Eden + 两个 Survivor，朝生夕死的小对象，复制算法，Minor GC 频繁但快）和老年代（长期存活的，标记整理，Full GC 慢）。对象熬过一次回收年龄 +1，到 15 岁进老年代——背住”15”这个数。

3.3 类加载过程 + 双亲委派 ★

类加载五步（说得出名字即可）：加载（读字节码）→ 验证 → 准备（静态变量给默认值）→ 解析 → 初始化（静态变量赋真值、执行静态代码块）。

双亲委派 ★（高频）——类比：小孩想买刀，店员不直接卖，先请示爹，爹请示爷爷。一个类加载请求，当前加载器先一路向上委托给最顶层（启动类加载器），父级说”我管不了/没这个类”才退回给下一级自己加载。 为什么要这样：安全 + 唯一——任何人写的 java.lang.String 都会被顶层的官方版本抢先加载，你伪造的核心类永远没机会生效（防止核心 API 被篡改），同一类全局只加载一份。

3.4 四种引用（低频，知道名字）

强引用（绝不回收）> 软引用（内存不够才回收）> 弱引用（下次 GC 必回收）> 虚引用（形同虚设，只为回收通知）。

四、多线程并发

4.1 ★ 进程和线程的区别（和 Python 一起考，必看第六章勾连）

类比：进程 = 一间厨房，线程 = 厨房里的厨师。多进程 = 开分店（每店独立采购、互不影响，但开新店成本高）；多线程 = 一间厨房加厨师（共用厨房的锅碗（共享内存），沟通方便但会抢锅——要加锁，且一个厨师打翻煤气全店遭殃——一个线程崩可能带崩进程）。

30 秒答案：进程是资源分配的基本单位（独立内存空间），线程是 CPU 调度的基本单位（共享所属进程的内存）。进程隔离好但创建开销大；线程轻量但共享内存带来竞争问题，需要同步机制。

4.2 线程的创建方式

30 秒答案：三种——①继承 Thread 重写 run；②实现 Runnable（推荐——不占继承名额）；③实现 Callable + FutureTask（能有返回值、能抛异常）。真生产里都用线程池，不手动 new。

4.3 ★ 线程的生命周期（五种状态）

30 秒答案：新建（New，还没 start）→ 运行（Runnable，就绪+运行统称）→ 阻塞/等待（等锁、sleep、wait）→ 终结（Terminated，run 跑完）。sleep 到点自动醒，wait 要别人 notify 才醒。

sleep vs wait（经典追问答）：sleep 是Thread 的方法、不放开锁（抱着锁睡觉）；wait 是 Object 的方法、放开锁（让出去等通知）——必须写在 synchronized 里。

4.4 ★ synchronized 和 Lock / volatile

synchronized 类比：单间厕所的门锁——谁先锁上谁用，后面的人门口排队（阻塞），上完自动开（出了代码块自动释放）。JDK6 后优化了（偏向锁→轻量级锁→重量级锁逐步升级），性能已经不错。

volatile 类比：白板公告——每个线程有自己抄的小抄（工作内存），volatile 强制”改了立刻写到白板、用之前必须重看白板”（可见性）；但它不排队（不保证原子性——i++ 这种多步操作照样能出错），只适合一写多读的场景（如开关标志位）。

30 秒答案：synchronized 保证原子性+可见性+有序性，锁住代码块同一时刻一个线程进；volatile 只保证可见性和禁止指令重排，不保证原子性。需要互斥用前者，状态标志广播用后者。

4.5 ★ 线程池（企业必备，最高频）

类比：打车软件的司机池——提前养一批司机（核心线程），单子来了派车；单多到派不完，加临时司机（非核心线程）；临时司机闲超过keepAlive时间就下班（回收）；单子再多就排队（队列）；队都排满了就拒单（拒绝策略）。好处：不用每单现场招司机（线程创建销毁开销大）、司机数可控（不会无限扩张把系统压垮）。

30 秒答案：线程池七大参数核心四个——corePoolSize（常驻司机）、maximumPoolSize（最大司机数）、workQueue（排队队列）、拒绝策略（满了怎么办：抛异常/调用者自己跑/丢弃/丢弃最老的）。执行顺序：先占核心 → 满了进队列 → 队满加临时线程 → 到顶执行拒绝策略（这个顺序是最常考的坑：队列满了才加线程，不是人满了才排队）。

追问下限：为什么不用 Executors 静态方法创建——可能无界队列堆积或线程无限增（OOM 风险），阿里规范要求 new ThreadPoolExecutor 手动指定参数。

4.6 死锁（必考，你的美团简历里有现成勾连）

类比：两个小孩，一个抱着球要拍子，一个拿着拍子要球，都在等对方先给——谁也不撒手，谁也玩不了。

30 秒答案：死锁四条件——互斥（一次一人用）、持有并等待（抱着现有的等新的）、不可剥夺（不能强抢）、循环等待（A 等 B、B 等 A）。破任意一条即可预防，工程上最常用的是按固定顺序加锁（都先拿球再拿拍子，就永远循环不起来）。

勾连简历：美团巡检的”同一时刻只允许一个升级/回滚在跑”就是防并发互踩；你开源插件 updater 的并发互斥同理。

五、Spring / SpringBoot

5.0 先说清两者关系

Spring 是全家桶框架（核心是 IOC 容器 + AOP）；SpringBoot 是 Spring 的”懒人包”——约定优于配置，开箱即用（不用写一堆 XML）。关系像”毛坯房（Spring）“和”精装公寓（SpringBoot）“。

5.1 ★★ IOC 控制反转（Spring 灵魂，必考）

类比：自己做饭 vs 点外卖。以前（无框架）：对象要什么依赖自己 new（自己买菜做饭——类里 new MySqlDao()，换数据库就改代码）；IOC 时代：你只声明”我需要什么”（@Autowired），容器做好送上门——做饭的控制权从你手里反转给了容器（外卖平台）。依赖注入 DI 是实现手段：容器把依赖”注射”进你的字段/构造器。

30 秒答案：IOC 是把”对象的创建和依赖管理”从程序员手里交给容器——解耦（换实现只改配置不改代码）、统一生命周期管理。DI（依赖注入）是它的实现方式。勾连简历：“FastAPI 的依赖注入是同一个思想，我在神农项目里天天用——两个语言在框架设计上互通，这也是我说 Java 上手快的原因。”（这句是第六章的预告，务必会说。）

5.2 ★ AOP 面向切面

类比：学校门口的保安——所有学生（所有方法）进出都要过同一道安检（日志/事务/权限），但每个班级（每个业务类）完全不用自己写安检代码。切面 = 横切在各条业务线上的公共逻辑（把”每个方法都要记日志”这件事从业务代码里抽出来，统一织入）。

30 秒答案：AOP 把日志、事务、权限这类横切关注点从业务代码中抽离，通过动态代理在方法前后统一织入。核心概念：切面（要插入的逻辑）、切点（在哪些方法插）、通知（方法前/后/环绕）。典型应用：@Transactional 声明式事务、统一日志。

5.3 Bean 及其生命周期

类比：员工从入职到离职。实例化（招进来）→ 属性注入（发工牌配电脑）→ 初始化前处理 → 自定义初始化（岗前培训）→ 使用（干活）→ 容器关闭时销毁（离职交接）。

30 秒答案：实例化 → 属性填充 → Aware 回调 → BeanPostProcessor 前置 → 初始化（init-method/@PostConstruct）→ 后置 → 单例放进容器使用 → 容器关闭时销毁回调。默认单例（全容器一个实例）；作用域还有 prototype（每次新建）等。

5.4 ★ SpringBoot 为什么”开箱即用”

30 秒答案：两个机制——起步依赖（spring-boot-starter-web 一个坐标把 Web 需要的几十个 jar 按兼容版本配齐——套餐代替单点）和自动配置（@SpringBootApplication 启动时扫描”你引入了什么”，按约定自动装配对应的配置类——检测到引了 Web 就自动配好 Tomcat 和 SpringMVC）。约定优于配置：都按默认来，要改才写配置。

勾连简历：“FastAPI 的’装好就能跑、/docs 自动文档’是同一设计哲学，我在实习里对比着体会过。”

5.5 常用注解速记

注解 干什么
@SpringBootApplication 启动类三合一（配置+自动配置+扫描）
@RestController @Controller + @ResponseBody：这个类的返回值直接是数据（JSON）不是页面
@RequestMapping / @GetMapping / @PostMapping 路由登记——对应 FastAPI 的 @app.post(“/ask”)
@Autowired / @Resource 注入依赖（容器送外卖）
@Service / @Component / @Repository 把类注册成 Bean（交给容器管）
@Value 读配置文件注入值
@Transactional 声明式事务（AOP 典型应用）

5.6 Spring MVC 请求流程（中频）

30 秒答案：请求 → 前端控制器 DispatcherServlet（总调度）→ 查路由（HandlerMapping）→ 执行对应 Controller 方法 → 返回结果经视图解析/转 JSON → 响应。类比：前台接线员按分派表找到坐席，办完把结果递回前台返回给客户——和你 FastAPI 三层”接线员/前台/坐席”是同构的。

六、勾连你简历的题（必看——差异化武器，别人没有）

6.1 “你主力是 Python，为什么 Java 也写上了？” ★

“Python 是我实习主力，Java 是本科软件工程的课程基础加自学做的 SpringBoot 项目。后端这套东西——HTTP 服务、数据库、分层架构、框架的 IOC/AOP——语言只是皮，我在 Python 里都完整做过（FastAPI 项目、数仓 SQL），Java 对我是’换语法不换思想’，所以也如实写了有开发经验。”

6.2 “Python 和 Java 有什么区别？” ★

“四个层面：①类型——Java 静态类型（变量类型编译时定死，错在写时就报），Python 动态类型（跑起来才知道，灵活但大项目重构险）；②执行——Java 编译成字节码跑在 JVM 上（快），Python 解释执行（灵活但慢）；③并发——Java 多线程是真并行（抢占式），Python 有 GIL，同一进程同时只跑一个线程，所以我在神农项目里用异步事件循环解决 I/O 并发，CPU 密集要多进程——这个差别我是实际踩过的；④生态——Java 企业后端（银行电信国企）深厚，Python 是 AI/数据科学第一语言。我的组合正好：AI 应用用 Python，企业服务懂 Java 的路数。”

6.3 “GIL 和 Java 的并发模型对比”（若面试官顺着问）

“GIL 让 Python 多线程无法利用多核做并行计算，I/O 并发靠 asyncio 事件循环；Java 线程直接映射操作系统线程，真并行，但共享内存要自己加锁（synchronized/Lock），并发工具丰富（线程池、ConcurrentHashMap）。一个’限制并发换简单’，一个’给你全部能力也给你全部责任’。”

6.4 “SpringBoot 和 FastAPI 都用过，说说对比” ★（好题，主动创造机会）

“同构的地方：都是’框架替你干杂活’——路由登记（@app.post vs @PostMapping）、依赖注入（同一个 IOC 思想）、参数校验（Pydantic vs Bean Validation）、自动文档（/docs vs swagger）。差异：SpringBoot 生态是企业级全家桶（事务、安全、监控开箱即用），启动重；FastAPI 轻快、原生异步，特别适合我的 AI 服务场景（等模型返回的几秒里事件循环还能接别的请求——Spring 的传统 servlet 是一请求一线程，异步要用 WebFlux）。选型上：AI 应用后端我选 FastAPI，重业务系统我理解为什么企业选 Java。”

6.5 “Java 里你怎么做你美团那个巡检任务？”（压轴勾连）

“思路不变语言变：分片扫描用线程池（ThreadPoolExecutor 固定 10 线程）提交 100 个分片任务；任务去重/幂等一样靠唯一键；定时调度用 Spring 的 @Scheduled 或 Quartz。核心是分片、幂等、断点续扫这套方法论和语言无关——我在 Python 里实现过，用 Java 重写是体力活不是难题。”

== vs equals ==比地址，equals比内容（需重写）；Integer 缓存 -128~127
String 不可变 final 字符数组；好处：共享安全、线程安全、哈希稳定；拼接用 StringBuilder
三大特性 封装（售货机）、继承（子承父业）、多态（猫喵狗汪）
重载/重写 重载=同类同名不同参（编译期）；重写=子类盖父类（运行期）
接口/抽象类 接口=合同可多实现；抽象类=半成品图纸单继承
HashMap 原理 数组+链表+红黑树；hash 定位、冲突拉链、链8树化、因子0.75扩容翻倍
ArrayList/LinkedList 数组查快插慢；链表插快查慢；日常 ArrayList

JVM 内存 共享：堆（对象）+方法区；私有：栈（方法）+计数器
判垃圾 可达性分析：GC Roots 出发不可达即回收

进程/线程 进程=厨房（资源单位）；线程=厨师（调度单位）共享内存
sleep/wait sleep 抱着锁睡到点醒；wait 放锁等 notify
synchronized/volatile 前者全保障（厕所锁）；后者只可见性不原子（白板公告）
线程池参数 核心/最大/队列/拒绝；流程：核心满→排队→队满加线程→顶了拒绝；不用 Executors（OOM 风险）
死锁四条件 互斥、持有等待、不可剥夺、循环等待；破一条即防（固定顺序加锁）

AOP 横切逻辑统一织入（门口保安）：日志/事务/权限
Bean 生命周期 实例化→注入→初始化→使用→销毁；默认单例
SpringBoot 开箱即用 起步依赖（套餐）+自动配置（检测装配）
@RestController = @Controller+@ResponseBody：返回值直接是 JSON
Python vs Java 静态vs动态类型；编译vs解释；真多线程vs GIL；企业vs AI 生态
